# Free seller verification entry design

The existing Seller Growth Program owns seller review. Its `seller_verifications` table, seller-only read RPC, submission RPC, administrator review RPC, trust-signals view, and badge component remain authoritative. This change makes the workflow visible and resolves status inconsistencies without collecting identity documents.

Authenticated sellers see a clear **Apply for Free Verification** action on their own profile and in Account Settings. Both lead to the existing seller-growth settings page, where a single statement about how the seller sources and describes items is submitted. The page explains that staff review marketplace profile, listings, and account activity; it does not claim government ID or identity checks. Pending applications have no submit control. Approved sellers see **Verified Seller** only after the admin RPC records approval. Rejected applicants see the reason and the existing seven-day cooldown. Revoked sellers may reapply, as the existing submission RPC permits. More-information requests can be answered on the same application. Program-off state remains visible but honest about being paused.

The current SQL permits an already verified seller to submit another application and an administrator to decide their own application. A forward migration corrects both boundaries and makes the public badge view depend on the latest application status. It introduces no table or authorization grant. Existing history remains intact. The migration is required before this app version, and the existing application and database feature switches must be enabled for users to submit.

Administrator review continues through `/admin/seller-growth`; the UI presents only actions valid for each status. The route and RPC still enforce admin authorization. Tests cover statuses, application/API security, SQL guard, badge visibility, browser interaction, and responsive layout. No production data or settings are changed automatically.
