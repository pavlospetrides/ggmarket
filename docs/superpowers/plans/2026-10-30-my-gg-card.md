# My GG Card implementation plan

**Spec:** `docs/superpowers/specs/2026-10-30-my-gg-card-design.md`

**Global constraints:** strict TDD; preserve supplied physics/design; no production services; no storage changes; no commit/push/deploy.

## Task 1: Domain contract

Write failing tests for exact theme mapping, defaults, strict validation, trimming, 80-character boundary, and rejection of unknown keys/themes/control characters. Add `lib/gg-card.ts`, types, and `ggCardSchema`.

## Task 2: Database security

Write migration-contract tests for table constraints, RLS, owner/public read policies, active-user write checks, suspension trigger, timestamp trigger, and grants. Add one immutable migration.

## Task 3: Authenticated mutation

Write route tests for unauthenticated, malformed, unknown-key, successful owner upsert, and database failure responses. Add `PATCH /api/gg-card` using the normal session client.

## Task 4: Server data flow

Write data/page tests proving private owner fetch, public-only visitor fetch, no default data disclosure, and serializable props. Extend profile loaders and both profile pages.

## Task 5: Lanyard component and lifecycle

Write physics/lifecycle tests first. Add the supplied component under `components/ui/lanyard-badge.tsx`, preserving mechanics while adding visibility, offscreen, reduced-motion, and cleanup lifecycle gates.

## Task 6: Card section, viewer, and customization

Write component tests for owner/visitor controls, private behavior, accessible dialog, validation/error states, theme selection, save, and dynamic loading. Add profile integration and responsive styles.

## Task 7: Browser and security regression coverage

Add Chromium/WebKit tests for view/customize/visibility, keyboard/focus/reduced motion, drag/flip, lifecycle, cross-account denial, suspension, and mobile layouts. Keep mutation tests behind the existing isolated-target guard.

## Task 8: Verification

Run TypeScript, ESLint, Vitest, production build, real production-server HTTP/RSC smoke tests, Chromium, WebKit, security tests, and `git diff --check`. Run local Supabase tests only against a disposable instance; report tooling blockers explicitly. Perform a final whole-diff review without committing.
